# AI Quota Monitor 首版设计草案

本文档记录 v0.1 已冻结的需求、技术选择和兼容边界。第 3 至第 5 节已经落地到代码并
完成软件与硬件验收。

2026-09-16 实现核对：PC Agent（App Server 客户端、归一化、HTTP 只读缓存）已通过
41 项单元测试，并在本机循环地址上完成 HTTP 冒烟验证；ESP32-S3 固件代码已写完，
已通过只读 `-fsyntax-only` 语法自检和 Arduino IDE 编译、烧录，实机正常连接 Wi-Fi、
PC Agent 并显示 Codex 双窗口额度；BOOT、断网、过期状态、错误响应与恢复路径均已
完成实机验收。

## 1. 产品目标

用一块 ESP32-S3 + OLED 设备快速查看 AI 服务商的额度状态。设备应在桌面上持续显示
关键信息，用户通过 BOOT 按键切换服务商，而不需要打开网页或终端。

首版只接入 Codex，优先验证数据链路、额度口径、页面可读性和离线行为，再扩展智谱、
商汤日日新、OpenRouter 等服务商。

## 2. 首版需求

### 2.1 功能需求

1. 获取 Codex 的额度信息。
2. 显示剩余额度和重置时间。
3. 显示当前数据更新时间或数据状态。
4. BOOT 按键产生一次明确的切换事件，并以服务商列表为导航抽象。
5. 数据暂时不可用时显示加载、过期或错误状态，不能静默显示不明来源的旧值。
6. 后续新增服务商时，显示层和按键导航尽量保持不变。

### 2.2 非功能需求

- 网络请求和显示刷新不能因为单次请求无限阻塞。
- 按键需要去抖，一次完整按下只产生一次切换事件。
- Token、密码和真实网络地址不能提交到仓库，也不应固化在固件中。
- 数据源发生字段缺失或服务商暂时不可用时，设备应保持可操作并给出明确状态。

### 2.3 登录操作安全边界

- 本项目禁止 Agent 自行登录 Codex。除非用户针对该次登录操作完成二次明确确认，Agent
  不得执行 `codex login`、登录启动／取消、登出、刷新认证状态，或修改 Codex 本地凭据。
- 用户提出“修复登录”“再试试”“检查登录”等泛化要求，不构成本次登录授权。需要登录时，
  Agent 必须先说明具体操作、影响的登录主体和凭据存储，以及是否可能覆盖或使当前会话失效，
  再等待用户明确确认。
- 未获确认时仅可进行只读认证检查；认证失效由 PC Agent 返回 `auth_required`，由用户手动
  完成登录。

## 3. 建议的数据流

```text
┌────────────────┐    ┌──────────────────┐    ┌────────────────┐
│ 服务商数据源    │ -> │ 服务商适配器       │ -> │ 统一额度快照     │
└────────────────┘    └──────────────────┘    └───────┬────────┘
                                                       │
                                                       v
                                             ┌────────────────┐
                                             │ ESP32-S3 OLED  │
                                             │ 网络、导航、显示 │
                                             └────────────────┘
```

首版有两种主要部署方案：

| 方案 | 优点 | 风险 | 当前判断 |
| --- | --- | --- | --- |
| 本机或局域网桥接服务 | 凭据集中管理，便于处理网页登录、刷新和多服务商差异；ESP32 只处理简单数据 | 需要额外服务进程和网络可达性 | v0.1 采用，已实现 |
| ESP32 直接访问服务商 | 部署组件少，链路短 | HTTPS、凭据保护、接口差异和固件升级成本更高 | 暂不作为默认方案 |

v0.1 采用本机桥接：`pc-agent/` 复用本地 ChatGPT 登录态，通过 Codex App Server 读取
额度，`monitor.py` 在局域网暴露只读 HTTP 接口；固件只拉取已归一化快照，不接触
账号 ID、Token、Cookie 或原始响应。局域网 HTTP 鉴权方式尚未冻结，固件里没有写入
任何长期密钥。登录态检查按官方 App Server 协议调用 `account/read`，显式传入
`refreshToken=false`，只读取当前状态，不强制刷新或改变本地凭据。

## 4. 统一额度快照

v0.1 的 HTTP 契约已经冻结，`GET /api/v1/quotas/codex` 只读内存缓存，不会触发
App Server 查询：

```json
{
  "provider_id": "codex",
  "provider_name": "Codex",
  "plan": "plus",
  "status": "ok",
  "windows": [
    {
      "label": "5H",
      "remaining_percent": 80,
      "resets_at": 1789484262,
      "reset_in_sec": 3540,
      "reset_at_local": "09-15 17:52"
    },
    {
      "label": "7D",
      "remaining_percent": 12,
      "resets_at": 1789815007,
      "reset_in_sec": 168600,
      "reset_at_local": "09-19 18:50"
    }
  ],
  "updated_at_epoch": 1789466100,
  "updated_at_local": "16:35",
  "age_sec": 3.2,
  "message": null
}
```

- `status` 取值为 `ok`、`auth_required`、`unavailable`、`invalid_data`、`stale`。
- 窗口标签固定映射：300 分钟 -> `5H`，10080 分钟 -> `7D`；其余窗口不进入首版页面。
- `remaining_percent` 由 Agent 计算为 `clamp(100 - usedPercent, 0, 100)`；固件只做
  越界再夹取，不改变口径。
- `reset_at_local` 是 Agent 按本机时区格式化的 `MM-DD HH:MM`，固件不解析 epoch。
- `updated_at_epoch` 是最近一次成功更新的 Unix 秒，用于接口诊断；`updated_at_local`
  是 Agent 按本机时区格式化的 `HH:MM`，固件直接用它显示最近同步时间，不自行做
  Unix 时间与时区换算。
- `age_sec` 是缓存快照的实际年龄，Agent 侧超过 180 秒自行报告 `stale`；固件不
  读取该字段做过期判定（固件无 NTP、无可信墙钟），而是用 `esp_timer_get_time()`
  计算相对最近一次成功拉取的时间差，同样按 180 秒判 `STALE`。
- 失败与缺字段状态只出现在 `status` 和 `message` 中，不包含账号、Token、Cookie、
  credit ID、完整原始响应或内部错误栈。

## 5. 页面与按键行为

### 5.1 页面内容

硬件已按 SH1106 128x64 单页实现，5H 与 7D 两个窗口同时显示：

```text
CODEX   PLUS      OK
5H 80% [████████░░]
R      09-15 17:52
7D 12% [█░░░░░░░░░]
R      09-19 18:50
SYNC          15:55
```

- 文字块只传达比例，连续矩形进度条由固件用 U8g2 图形调用画出，不用字符拼凑。
- 剩余比例低于 20% 时该数值反白显示，保持静态，不做闪烁告警。
- 页脚正常显示 `SYNC HH:MM`；数据过期后保留旧值并改为 `STALE Nm`。
- 页首状态为设备侧优先：`WIFI`（连接中）、`OFF`（Agent 不可达），否则显示
  Agent 报告的状态：`OK` / `LOGIN`（需登录）/ `SRC`（Agent 可达但数据源取不到）/
  `BAD` / `STALE`。五取值状态与第 4 节的枚举一一对应。
- 请求失败只更新状态，不清空上次有效快照。

### 5.2 BOOT 导航

- 服务商列表按固定顺序注册。
- 一次稳定按下只推进到下一个服务商，越过列表末尾后回到第一个。
- 当前 v0.1 列表只有 Codex；导航接口仍按多服务商设计，不能在显示层写死为 Codex。
- 某个服务商没有有效数据时，仍可切换到该页面并显示不可用状态。
- 去抖和输入处理应使用非阻塞时序，不用长时间 `delay()` 阻塞数据刷新。

## 6. 已冻结事项与兼容边界

施工中已定：Codex 数据来自本机 ChatGPT 登录态下的 App Server，只解析
`rateLimitsByLimitId.codex`；额度口径为 `clamp(100 - usedPercent, 0, 100)`，窗口为
300 分钟和 10080 分钟；重置时间与最近同步时间均按 Agent 本机时区显示；刷新周期为
App Server 通知驱动、PC 端 60 秒兜底、ESP32 10 秒拉取、OLED 1 秒本地刷新；
缓存 3 分钟无成功更新即过期。

- 固件按 SH1106 128x64、I2C 总线 SDA GPIO8 / SCL GPIO9 实现，BOOT 按键取 GPIO0、
  按下为低电平；当前硬件与页面已通过实机验收。
- v0.1 的 PC Agent HTTP 接口不设应用层鉴权，只允许在可信局域网使用，不应暴露到
  公网或不受信任网络；固件不保存 ChatGPT Token、Cookie 或账号凭据。
- 若后续 App Server 协议不再提供所需字段，或登录类型不是 ChatGPT 登录态，需要重新
  核对官方协议和实现边界。
